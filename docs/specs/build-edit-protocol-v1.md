# BUILD Edit Protocol v1 — anchored semantic edits

Status: **implemented (offline-qualified; no live experiment run against it yet)**
Experimental lineage: Pilot A V8–V11 falsified every model-configuration knob for BUILD
publication (budget 16k→32k at fixed `low` reasoning: 0/6 valid low-effort opportunities
published; max budget utilization 43%). The falsified variable was never capacity — it was
the **interface**: BUILD required the model to author byte-sensitive transport markers
(`<<<SLE-PATCH path="…" base="<sha256>">>>` … `<<<END-SLE-PATCH>>>`, `SLE-ARTIFACT` blocks)
and zero-fuzz unified-diff geometry. Six for six, the model produced the right semantic edit
and failed the serialization (hunk-count inflation, oldStart drift, context-whitespace
corruption, truncated markers).

This spec removes the tasks instead of training them. Principle (already the system's
stated one, DDR-034): **the model proposes; Stratum materializes.** Unified diff survives —
as *evidence generated by Stratum after the bytes are decided*, never as an instruction
language authored by the model.

## 1. The anchor primitive

A **source anchor** is an opaque, content-addressed reference minted by Stratum at the
moment the model reads an exact source region through `read_source_slice`:

```json
{
  "anchor_id": "src_7f42a9c1d0e3b5a6",
  "path": "apps/ai-server/rag-worker-service/main.py",
  "base_sha256": "<full-file sha256 at read time>",
  "start_line": 980,
  "end_line": 1020,
  "content_sha256": "<sha256 of the returned slice content>"
}
```

- `anchor_id` = `"src_" + first 16 hex of sha256` over the canonical binding string
  `path \0 base_sha256 \0 start_line \0 end_line \0 content_sha256`. Deterministic (the
  same read in the same file state remints the same id — replay can recompute ids from
  evidence) and opaque (it carries no positional or hash authority by itself).
- The **registry is the run-scope authority**. One `AnchorRegistry` exists per step
  execution. `resolve(anchor_id)` consults only anchors minted in *this* execution:
  an anchor from another step, another iteration, or another run is **unknown** —
  fail-closed, repairable ("re-read the region").
- Minting happens inside the loop's `read_source_slice` tool-result path. The tool result
  gains the `anchor` field; everything else about the result is unchanged. `read_file`
  (whole-file) and `list_directory` mint **no** anchors in v1.

## 2. The proposal (the only thing the model authors)

BUILD's final submission is a `submit_result` tool call (the existing structured channel,
already live-proven on this provider by the define-work contracts) carrying:

```json
{
  "edits":   [ { "anchor_id": "src_…", "replacement": "<new source bytes for the anchored span>" } ],
  "creates": [ { "path": "apps/…/new_file.py", "content": "<whole new file>" } ]
}
```

That is the entire schema (`.strict()` — any additional key, e.g. a model-supplied hunk
count, is a decode rejection with a bounded in-loop repair). Ops in v1: `replace`
(anchor-referenced) and `create_file` (new-path). No `delete` (an empty `replacement`
deletes the anchored span), no old-text/new-text JSON (V9 proved the model drops bytes
when copying "old" text; anchors make that field nonexistent).

## 3. The ActionContract seam (sibling of OutputContract, not a hack)

`OutputContract<T>` materializes ONE canonical artifact string. BUILD stages a MULTI-FILE
changeset against repository state — a different shape, so it gets a sibling seam:

```ts
interface ActionContract<T> {
  readonly modelSchema: z.ZodType<T>;            // single structural authority → submit_result projection
  readonly schemaAnnotations?: SchemaAnnotations;
  readonly contextTeaching?: (ctx) => string | undefined;
  validate?(value: T, ctx: ActionContractContext): readonly ContractDefect[];  // in-loop, repairable
  stage(value: T, ctx: ActionStageContext): Promise<
    { ok: true; changeset: StagedChangeset } | { ok: false; error: string }>;  // post-loop, authoritative
}
```

Identity is the trusted declaration exactly like OutputContract: the `WorkflowStep`
declares `actionArtifact: { type }`, the composition root registers the implementation
(`'build-changeset'`); no model-selected contract identity. Declaring both `outputArtifact`
and `actionArtifact` on one step is an authoring error (fail closed, no LLM call), as is an
`actionArtifact` type with no registered contract.

Two-phase validation discipline, mirroring the existing patch path:

| Phase | Where | Repairable? | Checks |
|---|---|---|---|
| `validate` | inside the loop (result-repair budget: 1) | yes | shape (zod), empty changeset, unknown/foreign anchor ids, duplicate anchors, duplicate create paths, edit/create path conflicts, unsafe create paths, extension allowlist, editPolicy authorization |
| `stage` + publication gates | runner, after the loop | **no** (fail closed, like a stale SLE-PATCH base today) | anchor re-resolution, disk bytes exist, `sha256(disk) === anchor.base_sha256`, overlap re-check, role ceiling, editPolicy re-check, inter-step ownership/protection, required-edit-path satisfaction |

## 4. Materialization (Stratum does what the model used to)

For each `replace`: read the file from disk, verify the disk sha256 equals the anchor's
`base_sha256` (stale → fail closed), splice `replacement` into the exact anchored line span
(bottom-up, so earlier spans keep their coordinates; empty replacement = span deletion),
compute final bytes. For each `create`: the path must not exist on disk; bytes are the
proposal's content. Multiple edits to one file must share the frozen base, must not
overlap, and are applied in one deterministic pass; the file is written once.

Stratum then runs the **existing publication boundary, unchanged**: `toSafeRelativePath`
path safety, builder deny-prefixes / role ceilings, `editPolicy.allowedEditPaths`,
`requiredEditPaths` (creates can never substitute for a required edit), inter-step
`produced-file:` ownership protection, single write pass with partial-publication
evidence, post-write sha256/size integrity verification, provenance rows
(`produced-file:` for creates; **`applied-edit:`** for replaces — distinct from the legacy
`applied-patch:`). Additionally: one `anchored_edits` summary on the run result
(op, path, anchor_id, before/after hashes) and a Stratum-generated unified-diff audit file
(`<nodeId>-anchored-diff.patch`, never-overwrite naming, best-effort persistence) — the
diff is **derived evidence**, computed from the decided before/after bytes.

## 5. Failure classes made impossible by construction

| Campaign failure | v1 status |
|---|---|
| hunk count wrong (V9-1, V11-3) | impossible — model supplies none; extra keys are schema rejections |
| oldStart drift (V9-3) | impossible — no positional fields exist |
| context whitespace corruption (V9 replay) | impossible — old bytes never leave Stratum |
| base sha copied wrong (V11-2) | impossible — the anchor owns it; the model never types a hash |
| malformed `SLE-PATCH` marker (V11-2) | impossible — no textual patch marker exists on this path; a textual patch in an end_turn reply is transport-`absent` and can never reach an applier |
| malformed `SLE-ARTIFACT` marker | impossible for the BUILD result — new files are `creates` entries |
| wrong diff line prefixes / missing hunk header | impossible — the model authors no diff |
| path-permission violations | unchanged enforcement, now pre-checked repairable (editPolicy) + authoritative (gates) |

## 6. What is deliberately NOT changed

- **Model configuration**: the P1 experiment keeps the exact V11 execution regime
  (DESIGN/PLAN 32k default, TEST 32k `low`, BUILD 32k `low`). The protocol is the sole
  intervention.
- All non-BUILD stages, transports, prompts, and evidence formats are byte-for-byte
  unchanged; `read_source_slice` results on non-anchor steps are unchanged (no `anchor`
  field).
- No fuzzy matching anywhere: no "nearest region", no whitespace tolerance, no
  similarity search. Unknown anchor / stale base / overlap / unauthorized path = fail
  (repairable in-loop only where listed in §3).
- The textual SLE transport remains in the codebase (legacy path, other roles); BUILD
  simply stops negotiating it because its declaration now resolves to an ActionContract,
  which routes negotiation to the submit-result channel by the existing rule
  (schema present + multi-turn provider ⇒ submit-result transport).

## 7. Qualification gate (before any live experiment)

1. This spec.
2. Offline tests: anchor minting/registry scoping; exact-byte splicing (whitespace,
   trailing-newline edges, span deletion); schema strictness; every §3 validate defect;
   staging staleness/creates/existing-path rules; the full runner publication path with a
   stub multi-turn provider (investigation → anchor → submission → gates → writes →
   integrity → provenance); in-loop repair on a rejected proposal; repair exhaustion
   fail-closed; cross-execution anchor rejection; textual-patch-cannot-reach-applier pin;
   **regression-impossibility pins for V9-1, V9-3, V11-2**; legacy-path byte-invariance
   (non-anchor steps' tool results unchanged).
3. Replay qualification: the archived V9-1 / V9-3 attempts (whose "intended" final bytes
   were previously recovered by count/anchor/whitespace super-normalization) are re-expressed
   as anchored proposals against the same pinned base; the staged final bytes must equal the
   recovered finals byte-for-byte. V11-3's `SLE-ARTIFACT` new file is re-expressed as a
   `creates` entry and must stage to identical bytes.

Only after all three pass does the preregistered P1 protocol experiment (V11 configuration,
unchanged, sole variable = BUILD output protocol; primary hypothesis: ≥2/3 BUILD
publications) become runnable.
